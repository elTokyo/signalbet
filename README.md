# ⚽ Bet Bot v2

Telegram-бот для футбольных прогнозов: напоминания, парсинг Discord, мониторинг Fonbet, ролевой доступ.

## Возможности

- 🤖 **Авто-парсинг** прогнозов из Discord-канала — дата матча определяется по самому матчу, а не по возрасту сообщения; правки сообщений подхватываются
- 📥 **Ручное добавление** через `/add` (админы)
- 🔔 **Напоминания** за 30 и 5 минут до матча
- 🔴 **Мониторинг Fonbet** — уведомление когда матч вышел в прематч/лайв + коэффициенты
- 🗑 **Автоудаление** через 5 минут после старта
- 🔒 **Авторизация по паролю** + whitelist
- 👥 **Роли**: админы управляют, юзеры только смотрят
- 📢 **Рассылка** всем юзерам (`/broadcast`)
- 📨 **Обратная связь** от юзеров (`/feedback`)
- 💾 **Хранение в GitHub Gist** — данные переживают редеплои
- 📋 **Общий список** прогнозов для всех пользователей

## Команды

### Для всех авторизованных
- `/start` — начало / запрос пароля
- `/list` — список активных прогнозов
- `/feedback` — отправить отзыв или баг-репорт админу
- `/commands` (или `/comands`) — полный список команд; админам показываются и админские
- `/today` — матчи на сегодня и что с ними на Фонбете (ищу / в линии / в лайве / не найден)
- `/quiet 23 8` — тихие часы (с 23:00 до 8:00 по твоему часовому поясу), `/quiet off` — выключить
- `/block Poland` / `/unblock Poland` — не получать матчи страны (`/block` без аргумента — список)
- `/unmute` — вернуть заглушённые матчи

### Только для админов
- `/add` — добавить прогнозы
- `/delete <id>` — удалить один
- `/clear` — очистить все
- `/settings` — настройки (часовой пояс, тумблер Fonbet)
- `/broadcast` — рассылка всем пользователям
- `/users` — список авторизованных
- `/ban <id>` / `/unban <id>` / `/remove <id>` — управление доступом
- `/debug` — диагностика конфигурации
- `/checkfonbet` — матчинг прогнозов с Фонбетом (видно статус ЛИНИЯ/ЛАЙВ и признак)
- `/bk [N]` — проверить прогноз №N на BetBoom / Winline / Лиге Ставок
- `/voice` — диагностика слежения за войсом Discord (видит ли бот канал, где сейчас цель, когда было последнее событие)
- `/status` — здоровье бота: Фонбет, Discord, расписание, активные тревоги
- `/misses [N]` — почему последние матчи не нашлись на Фонбете; `/misses found` — что нашлось и по какому уровню
- `/undetermined` — матчи, дату которых бот не смог определить (кнопки «Сегодня / Завтра / Пропустить»)
- `/aliases` — запомненные пары названий команд; `/unalias <название>` — удалить ошибочную
- `/cancel` — отмена текущего ввода

## Настройка GitHub Gist

1. https://gist.github.com → filename `users.json`, body `{}` → **Create secret gist**
2. Скопируй ID из URL: `gist.github.com/user/<ID>`
3. https://github.com/settings/tokens → Generate (classic) с правом `gist`
4. Добавь `GITHUB_TOKEN` и `GIST_ID` в Railway

Файлы `predictions.json` и `settings.json` бот создаст сам.

## Диагностика и алерты (для админов)

- **Сторож здоровья** (`health.py`, проверка раз в минуту). Админам приходит сообщение, когда:
  Фонбет не отвечает 5 запросов подряд, Discord-клиент без соединения дольше 3 минут,
  перечит Discord-канала не проходил больше 30 минут. Тревога приходит один раз, затем
  одно сообщение «снова работает» с длительностью сбоя. Первые 3 минуты после старта не тревожим.
- **`/status`** — то же самое «по запросу»: когда Фонбет отвечал в последний раз, сколько событий,
  причина последней ошибки, состояние Discord, число прогнозов, матчей без даты.
- **Журнал матчинга** (`/misses`). Когда матч уходит из расписания, так и не найденный на Фонбете,
  в журнал пишется причина и три самых похожих события: «время старта отличается на 40 мин»,
  «названия 55% (<60%), страна/лига не совпали», «неоднозначно»… Журнал — последние 200 событий
  (в `predictions.json`, ключ `fonbet_journal`). По нему удобно подбирать пороги.
- **Матчи без даты.** Если бот не смог достоверно определить дату матча, админам приходит вопрос
  с кнопками «Сегодня 21.10 / Завтра 22.10 / Пропустить» (один раз на матч). Выбранная дата
  запоминается и не слетает при правках сообщения. Незакрытые вопросы — `/undetermined`.

## Названия команд: русский язык и память

- Прогнозы на русском («Нигерия. Кубок. Альфа — Бета») ищутся среди **русских** названий Фонбета —
  для них бот делает второй запрос с `lang=ru` (только когда такие прогнозы есть в окне мониторинга).
- Когда бот **уверенно** нашёл матч, хотя названия различались (уровень `same_slot` или слабая
  сторона при сильной другой), он запоминает пару «название из прогноза → название на Фонбете»
  (`fonbet_aliases` в `predictions.json`). Известная пара даёт 100% для этой команды в следующий раз.
  Ошибочную пару можно удалить: `/aliases`, `/unalias <название>`.
- Поиск идёт **от времени**: сначала отбираются события, стартующие в пределах ±15 минут от
  прогноза, и только по ним считается сходство названий — быстрее и меньше ложных совпадений.

## Личные фильтры уведомлений

Настраивает каждый пользователь для себя; действуют на напоминания, выход в линию/лайв,
«кривые», андердоги и довесок по другим конторам:

- **Тихие часы** — `/quiet 23 8`. Уведомления в этот интервал не приходят (и не копятся).
- **Заглушить матч** — кнопка «🔕 Заглушить матч» под уведомлением. Вернуть: `/unmute`.
- **Заблокировать страну** — кнопка «🚫 <Страна>» под уведомлением или `/block Poland`
  (название — как в начале прогноза, на том же языке). Вернуть: `/unblock Poland`.

## Как бот определяет дату матча (Discord)

В сообщениях обычно только время («18-00 А — Б»), без даты. Поэтому дата матча
привязывается к **моменту, когда матч появился в сообщении** (anchor), и
определяется один раз — потом она не «плывёт» вместе с текущим временем:

1. **Явная дата** — строка-заголовок секции («21.10», «Вторник, 21 октября»,
   «Завтра») или дата в самом прогнозе до времени («… 21.10 18-00 …»). «Завтра» и
   «послезавтра» считаются от момента публикации/правки, а не от «сейчас».
2. **Ближайшее вхождение времени после публикации** (прогноз — про будущие матчи):
   - время не раньше момента публикации → тот же день;
   - время раньше, а публикация вечерняя (с 18:00) → следующий день («вечерний пост на завтра»);
   - время раньше, матч ночной (до 06:00) → следующий день (после полуночи);
   - время раньше, публикация дневная → **дата неопределённа**: матч не добавляется,
     причина пишется в лог.
3. **Правка сообщения.** Матчи, которые были в сообщении раньше, сохраняют дату.
   Матчи, дописанные правкой, получают дату от времени правки. Изменилось время у
   известного матча — обновляется его запись (флаги напоминаний сбрасываются),
   новая запись не создаётся.
4. **Актуальность** решается по дате каждого матча: начавшийся более чем
   время жизни прогноза (`DELETE_AFTER_MINUTES`, не меньше 16 мин) назад в расписание не попадает и не возвращается, пока
   автор не перенёс его на будущее время. Возраст сообщения роли не играет
   (читается только история не старше 72 часов — чисто оптимизация).

Идентификатор сообщения — постоянный `message_id` Discord. Матч внутри сообщения
идентифицируется нормализованными названиями команд (не временем — оно может
меняться). Журнал «сообщение → матчи → дата/anchor/статус» хранится в Gist в
`predictions.json` под ключом `discord_ledger` (отдельный файл не нужен, хранится 4 суток). Матч, дату которого достоверно определить нельзя, не пропадает молча — админу уходит вопрос с кнопками (см. «Диагностика и алерты»).

Если автор убрал матч из сообщения (или удалил сообщение) и матч ещё не начался —
он снимается с расписания; начавшийся остаётся (исчезновение прогноза не означает
отмену матча).

**Ограничения.** Если бот впервые видит уже отредактированное сообщение (например,
после потери журнала) и по публикации и по правке получаются разные даты — матч не
добавляется (в логе `дата НЕ определена`), а админ получает вопрос с кнопками. Дневной
пост с временем раньше публикации тоже считается неопределённым. Поправить пороги
можно в `match_dates.py` (`EVENING_POST_FROM_HOUR`, `NIGHT_UNTIL_HOUR`, `SAME_DAY_GRACE_MIN`).

### Логи

На каждое обработанное сообщение: id, время публикации/правки, итог (найдено / новых /
обновлено / убрано / восстановлено / пропущено: прошедших, с неясной датой, дублей) и
по каждому матчу — дата, основание, причина пропуска. `/syncdiscord` показывает те же
счётчики.

## Формат прогнозов

Триггер начала прогноза — слово **Футбол** или **Soccer**. Блоки на разное время
разделяются длинными тире (`-------`). Несколько прогнозов на одно время идут подряд.

```
Футбол. Нигерия. Кубок. 18-00 Эль-Шама — Эньимба п2 3+
-------------------------------
Футбол. Польша. 19-00 Уния — Спуйня п2 4+
Футбол. Чехия. 19-00 Пенчин — Коштялов ф1-4,5
```

Бот вытащит время для планировщика, остальной текст сохранит как есть. Дата, если она
указана, учитывается: строка `21.10` / `Завтра` над блоком или `21.10` перед временем.

## Мониторинг Fonbet

- Окно проверки: за 60 мин до старта → +15 мин после (прогноз гарантированно остаётся в листе до конца окна)
- Тик раз в 15 сек (горячее окно ±10 мин), холодные матчи — раз в 60 сек
- Fuzzy-сопоставление команд + сверка времени старта и возрастных маркеров

### Как бот находит матч на Фонбете

Для каждого прогноза из списка событий Фонбета отбираются кандидаты. Обязательно для всех:
возрастной маркер (U20/женские/дубль) совпадает, время старта отличается от времени прогноза
не больше чем на 15 минут. Дальше смотрится сходство названий команд (среднее по двум командам):

| Уровень | Порог | Условие |
|---|---|---|
| `base` | **60%** (было 80) | всегда |
| `same_slot` | **50%** | матч стартует в указанное время **и** страна/лига события совпадают со страной/лигой из прогноза |

Страна и лига события берутся из справочника `sports` в ответе API (`Страна. Лига`), в
прогнозе — из заголовка до времени («Poland. 4 Liga. …»). Если справочника нет или прогноз
написан другим алфавитом («Нигерия» против «Nigeria»), уровень `same_slot` не включается и
действует только базовый порог.

Если матч принят только по `same_slot`, а второй кандидат в той же лиге и в то же время
отстаёт меньше чем на 10 пунктов — выбор неоднозначен, матч считается не найденным (лучше
пропустить, чем прислать уведомление не про тот матч; много игр стартуют одновременно).
В `/checkfonbet` у найденного матча видны % совпадения, уровень и лига события.

### Линия vs Лайв

Статус определяется строго, по цепочке признаков (первый сработавший побеждает):

1. флаги `live` / `inLive` / `isLive`
2. поле `place`/`state` со словом live
3. событие есть в блоках со счётом/таймером
4. **время старта уже наступило → лайв**

Раньше использовался только п.1, из-за чего идущие матчи подписывались как
«прематч». Признак, который сработал, пишется в лог и в `/checkfonbet`.

Уведомления:
- `📋 Матч вышел в ЛИНИЮ!` — появился в прематче
- `🔴 Матч вышел в ЛАЙВ!` — начался (после линии)
- `🔴 Матч открыт сразу в ЛАЙВЕ!` — линии не было вообще, уведомление одно
- Во всех «лайв»-уведомлениях дублируется `📝 Прогноз` — даже если до этого приходило уведомление о линии

### Кривой матч и андердог

- `💰 КРИВОЙ МАТЧ!` — кэф на свою команду дошёл до порога прогноза (или сработало форовое условие)
- `🐶 АНДЕРДОГ!` — кэф на соперника ≥ 8.0 (только для ставок на победу)
- Сработали оба — шлётся «кривой матч», в нём видны кэфы обеих команд
- Отдельные тумблеры в `/settings`

### Проверка других контор

После уведомления о кривом/андердоге бот вдогонку проверяет **BetBoom, Winline
и Лигу Ставок** на наличие того же матча и того же рынка (П1/П2 или фора из
прогноза) и присылает найденные кэфы. Заменяет прежний каскад Леон → БетСити.

Парсер универсальный: он ищет в JSON структуры «две команды + коэффициенты»,
не зная заранее имён полей. Если контора сменит адрес API:

```bash
python bk_probe.py                    # перебрать всех кандидатов
python bk_probe.py https://новый/url  # проверить конкретный адрес
```

Рабочий адрес прописывается переменной `BETBOOM_API_URL` / `WINLINE_API_URL` /
`LIGASTAVOK_API_URL` — без правки кода. Проверить конкретный прогноз из бота:
`/bk 3`.

## Слежение за голосовым каналом Discord

- Следит за одним юзером (`DISCORD_VOICE_USER_ID`) в одном войсе (`DISCORD_VOICE_CHANNEL_ID`)
- Шлёт `🎧 ... зашёл` и `👋 ... вышел` всем авторизованным
- Уведомление о выходе откладывается на 60 сек: вернулся раньше — реконнект, молчим
- Кулдаун 10 минут на каждый тип события
- Тумблер `🎧 Заход в войс Discord` в `/settings`
- Нужен intent `voice_states` (входит в defaults, включается кодом) и доступ бота к каналу
- Если цель уже сидела в войсе, когда бот стартовал (например, во время редеплоя), события «зашёл» не будет — так устроен Discord. Дальше «вышел» сработает как обычно
- Не пришло уведомление → `/voice`: покажет, видит ли бот канал и не сидит ли цель в другом войсе

## Файловая структура

```
bot.py              ← точка входа, регистрация команд
config.py           ← переменные окружения
models.py           ← Prediction, UserSettings
parser.py           ← разбор прогнозов (+ явные даты в тексте)
match_dates.py      ← определение даты матча (чистые функции, без Discord/Gist)
health.py           ← состояние Фонбета/Discord, алерты админам
userprefs.py        ← личные фильтры (тихие часы, страны, заглушка), статус матча для /today
auth.py             ← авторизация и whitelist
storage.py          ← прогнозы и настройки (общий список)
gist_storage.py     ← бэкенд GitHub Gist
handlers.py         ← все команды и обработка текста
scheduler.py        ← напоминания + автоудаление + Fonbet
fonbet.py           ← клиент Fonbet API, fuzzy-матчинг (пороги 60/50 + страна/лига), линия/лайв, кривизна
```
